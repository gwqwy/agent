# nanoagent 插件生态：对齐 DeepSeek Harness「Everything is a Plugin」

## 调研结论（决定方案形状）

DeepSeek Harness（dsh）的插件体系 = **Cordis 微内核** + 三种声明层：
1. **ctx 编程模型**：插件通过 `ctx.provide(name, service)` 提供服务、`ctx.on(event, handler)` 订阅事件、`ctx.effect(fn)` 注册（必须返回 disposer，卸载时 LIFO 回滚）；fiber 状态机 PENDING→ACTIVE→DISPOSED
2. **包格式**：npm 包，`package.json` 声明 `dsh.bundle`，`cordis.patch.yml` 声明挂载位置；skills（SKILL.md）与 MCP 工具都是插件的产物
3. **管理方式**：`dsh plugin add/update` 装进 profile，GitHub topic `dsh-plugin` 发现

**诚实边界**：dsh 插件的 TS 代码体是进程内 Cordis 服务，Python 运行时无法执行。所以「支持 dsh 插件、支持所有格式」的落地方式是：nanoagent 自建一个 **Python 版 mini-Cordis**（对齐 ctx/effect/disposer 模型）作为原生格式，外加**格式适配器层**自动识别外来插件包、提取其中 Python 能消费的声明层（skills、MCP 服务器、配置），不可执行的代码部分明确提示。新格式通过适配器注册表无限扩展——这就是「所有格式」的实现机制。

## 改动清单（全部在 nanoagent/ 内，115 个现有测试不动）

### 1. `plugins.py` — mini-Cordis 内核 + 适配器层（核心新文件）
- `PluginContext`（对齐 dsh 的 ctx）：`provide(name, service)`、`on(event, handler)`、`effect(fn)`（fn 返回 disposer，统一入账本）、便捷入口 `ctx.tools.register(tool)` / `ctx.skills.add_dir(path)` / `ctx.mcp.add_server(cfg)`；`deactivate()` 按 LIFO 跑光 disposers，幂等（try/except 逐个吞错，对齐 dsh）
- `Plugin` 记录：manifest、format、state（`PENDING/ACTIVE/FAILED/DISPOSED`，对齐 fiber 状态机）、disposables 列表
- `PluginManager`：`scan(dir)` 逐目录探测格式 → `activate()` 建 ctx、调适配器装载 → `deactivate(name)`；`list()` 汇报每个插件提供了哪些工具/技能/MCP
- **格式适配器注册表**（`register_adapter(name, detector, loader)`，可扩展）：
  - `nanoagent`：`plugin.json` + `plugin.py`（`register(ctx)` 函数或 `TOOLS` 列表）
  - `dsh`：探测 `package.json` 含 `dsh` 字段或存在 `cordis.patch.yml` → 解析 skills 目录、`.mcp.json`/mcpServers 声明、patch 配置；`.ts/.js` 代码体标记 `skipped: ts-code` 并写明原因
  - `agent-skills`：纯 SKILL.md / skills/ 目录（Claude Code 等通用 Agent Skills 格式）
  - `mcp-only`：仅含 mcpServers JSON 的包
  - 兜底：含 `SKILL.md` 或 `plugin.json` 的任何目录都能被识别，否则报 `UnknownFormat`（列出找到了什么，方便加新适配器）
- 插件事件总线：`activate/deactivate/error` 事件，`ctx.on` 订阅者可监听

### 2. `skills.py` — Agent Skills（dsh/业界通用 SKILL.md 格式）
- `Skill`：name/description/body/path（frontmatter 用内置迷你 YAML 解析器，只支持 `key: value`，不引新依赖）
- `SkillRegistry`：`add_dir`（递归收 SKILL.md）、`list_summary()`（只给名字+描述——渐进式披露第一层）、`load(name)`（读全文——第二层）
- `use_skill` 工具（@tool 生成 schema）：模型按需调用加载全文，避免塞爆上下文；`Agent.enable_skills(registry)` 一行接入

### 3. `mcp.py` — 增加 `MCPManager`（对齐 dsh plugin add 的 MCP 形态）
- 配置文件 `.nanoagent/mcp.json`，格式用业界通用的 `{"mcpServers": {name: {command, args, env}}}`
- `add(name, cfg)` / `remove(name)` / `list()`（= 安装/卸载，写回 JSON）/ `connect_all()` → 得到可注册的 Tool 列表；复用现有 MCPServer

### 4. `bootstrap.py` — 一键装配
- `bootstrap_agent(base_url=..., api_key=..., model=..., config_dir=".nanoagent")` → 扫描 plugins/、skills/、mcp.json → 全部激活合并进一个 Agent → 返回 `BootstrapReport`（装了哪些插件、各提供什么、跳过了什么）
- 任何单个插件激活失败不影响其余（记录到 report.failed）

### 5. `manage.py` — 命令行管理（对齐 `dsh plugin` 子命令）
- `python -m nanoagent.manage install-plugin <本地路径|git URL>`（git URL 克隆到 `.nanoagent/plugins/`）
- `install-skill <路径|URL>`、`install-mcp <name> --command ... --args ...`、`remove-plugin/skill/mcp`、`list`（分栏展示插件/技能/MCP 及其来源格式）
- 无网络依赖：不做在线市场，`--registry <url>` 指向 JSON 索引即可留扩展

### 6. 测试（目标 +25 左右，总计 ~140）
- PluginContext：provide/on/effect、LIFO disposer 顺序、幂等卸载
- PluginManager：三种格式 fixture（nanoagent 原生、假 dsh 包含 package.json+SKILL.md+ts 文件、纯 skills 包）的探测/激活/跳过报告；坏插件不拖垮整体
- SkillRegistry/frontmatter/use_skill 工具（MockLLM）
- MCPManager 配置读写 + connect（复用现有 mcp_echo_server.py，无 mcp 包则跳过）
- bootstrap 端到端（MockLLM + 临时 .nanoagent 目录）
- 现有 115 个测试原样通过 + compileall

### 7. 文档
- `examples/11_plugins.py`：写一个临时插件目录 → bootstrap → Agent 用上插件的工具和技能
- README 新增「插件生态」节：目录结构、三种格式示例、dsh 兼容说明（含 TS 代码体不可执行的边界）、与 `dsh plugin` 命令对照表
- `__init__.py` 导出 PluginManager、SkillRegistry、MCPManager、bootstrap_agent

## 交付后架构图（会同步给你）
入口层(cli/server/manage) → 装配层(bootstrap) → 插件层(plugins: mini-Cordis + 适配器) → 能力注册(tools/skills/mcp) → 核心层(Agent/llm/memory/rag/multi)
